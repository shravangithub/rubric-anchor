Why it's different

Three rules, all enforced by tests

Not principles in a README — assertions in a test suite that fail if someone changes them.

Scored alone, never compared

Each CV is scored on its own against a fixed rubric; the ranking is produced afterwards by sorting numbers. Hand a scorer a list and it raises. A test scores a candidate, runs five others through, scores again, and asserts the number didn't move.

No quote, no score

Every model-produced claim must carry a span copied character-for-character from the CV, checked by substring in code. Paraphrase it and the claim is dropped. Hallucination becomes a string comparison.

A person makes the adverse call

Only two of eight gates may auto-reject — work authorisation and a legally required licence. Everything else, education included, routes to a human. The machine narrows the pool; a person says no.

How it works

One candidate at a time

  1. Parse the requirements onceThe JD becomes testable requirements with weights and gate types. A human approves this before any CV is read.
  2. Pull claims with evidenceEach fact extracted from the CV carries the exact line it came from.
  3. Verify the evidence in codeSubstring check against the source. A claim whose quote isn't verbatim in the document is dropped before it can influence anything.
  4. Redact identity, then compute the gatesName, institution and pronouns stripped. Years of experience calculated from dates — 22 of the parameters never touch a model.
  5. Score each parameter in isolationNo candidate is compared to any other. Order and batch size become irrelevant.
  6. Sort the numbers, then a recruiter decidesWith the full audit record attached: every value, the node that produced it, and every claim that was dropped.

Responsible use

What this does not do

Stated here rather than buried, because a screening tool that oversells itself is the problem it claims to solve.

  • It does not make your shortlist better at predicting talent. It makes it repeatable and explainable. Those are different claims and only the second one is honest.
  • It does not validate your rubric. A perfectly built system applying criteria that don't predict job performance will apply them consistently to everyone. The knowledge-graph layer is there to find that out — but it needs a few hundred hires and a couple of years before it says anything.
  • It catches noise, not bias. A system that is confidently wrong about a group looks perfectly settled. Only outcome tracking finds that.
  • Institution tier is deliberately not a parameter. College ranking is the strongest single proxy for socio-economic background in most markets. A test keeps it out.
  • Absence of public work is never a penalty. Employer IP policy, NDAs and unpaid-time inequality suppress GitHub activity independently of ability. Those parameters leave the composite rather than scoring zero.
  • The weights are considered judgement, not measured validity. Reweight for your context and record who approved it.
