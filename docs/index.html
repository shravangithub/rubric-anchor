The whole argument in fifty-three seconds

Twelve résumés reordered three times, one candidate measured against 247 fixed parameters, and what the graph remembers afterwards.

Three rules, all enforced by tests

Not principles in a README — assertions in a test suite that fail if someone changes them.

Scored alone, never compared

Each CV is scored on its own against a fixed rubric; the ranking is produced afterwards by sorting numbers. Hand a scorer a list and it raises an error.

A test scores a candidate, runs five others through, scores again, and asserts the number didn't move.

No quote, no score

Every model claim must carry a span copied character-for-character from the CV, checked by substring in code. Paraphrase it and the claim is dropped.

Hallucination becomes a string comparison rather than a judgement call.

A person makes the adverse call

Only two of eight gates may propose a rejection — work authorisation and a legally required licence — and a person confirms it with one click. If the CV doesn't say, that's an Unknown to ask about, never a fail.

The machine narrows the pool; a person says no. It also writes the plain-language explanation the newer rules ask for, naming who decided.

New in version 0.2, October 2026

Ready for a live model, and for the 2026 rules

Isolation removes order and batch effects. These close the gaps it leaves — each one a test that fails if someone removes it.

No gate closes an application

A failed work-authorisation or licence check now proposes a rejection. A person confirms it with one click before anything reaches the candidate.

Automated-decision rules increasingly require a reviewer with authority to change the outcome.

Unknown is not a fail

A CV that doesn't mention work authorisation hasn't said "no". It's recorded as Unknown and turned into a question for the candidate.

Found a real bug on the way: "no sponsorship required" was being read as not authorised.

Redaction, in code

Emails, phone numbers, profile links, gendered pronouns and the name line are removed before the model reads anything — and every quote is checked against the redacted text.

The audit keeps counts, never the removed values.

A CV can't write its own score

Lines that address the model — "ignore previous instructions", "SYSTEM:", hidden characters — are flagged, the CV goes to a person, and nothing quoted from those lines counts as evidence.

The prompt asks; this enforces.

Ranges and bands, not one run

A live model wobbles run to run. Each CV can be scored several times, still alone. Anyone whose range straddles the cut-off is borderline, and a person decides.

The fix for the 4th-to-11th swing in the experiment above.

Swap test and eval report

Change only a name or a pronoun and check the score doesn't move. One command runs stability, swaps and planted injections, and records the model and prompt version that produced the result.

Run it before switching any model on, and again when it changes.

Where scores stop being disposable

Every assessment becomes facts with provenance. The point isn't to screen anyone — it's to accumulate the record that answers the question no single requisition can: which of our criteria actually predicted a good hire?

Bi-temporal storage

Every fact carries when it was true and when you learned it. A promotion effective in March, recorded in June. Conflating those makes audit answers wrong — so you can reconstruct what the system believed on any past date.

Validity, not just separation

Did a parameter distinguish who you hired from who you rejected? That's circular — it measures your process. Did it predict who turned out good? That's the question. A parameter can separate strongly and predict nothing.

Selection bias, flagged

Performance data exists only for people you hired. Among hires, a weak score on one criterion must have been offset elsewhere — manufacturing spurious negative correlations. Flagged as artefact rather than reported as signal.

Counterfactuals & fairness

Drop a parameter and see whose outcome would change, measured as shortlist churn. Adverse-impact screening runs on aggregate counts with no path to a person — a test asserts the class contains no query.

One candidate at a time

  1. Parse the requirements onceThe JD becomes testable requirements with weights and gate types. A human approves this before any CV is read.
  2. Pull claims with evidenceEach fact extracted carries the exact line of the CV it came from.
  3. Verify in codeSubstring check against the source. A claim whose quote isn't verbatim is dropped before it can influence anything.
  4. Scan, redact, then compute the gatesLines written to the model ("ignore previous instructions…") are flagged and can never be evidence. Name, contact details, pronouns and any institutions you list are stripped before the model reads anything. Years of experience calculated from dates — 22 parameters never touch a model.
  5. Score each parameter in isolationNo candidate is compared to any other. Order and batch size become irrelevant.
  6. Score again, then band — don't rankEach CV is scored several times, still alone. Anyone whose range straddles the cut-off is borderline, and a person decides.
  7. A recruiter decidesWith the audit record attached: every value, the model and prompt version that produced it, and every claim dropped.

What this does not do

Stated here rather than buried, because a screening tool that oversells itself is the problem it claims to solve.

  • It does not make your shortlist better at predicting talent. It makes it repeatable and explainable. Those are different claims and only the second one is honest.
  • It does not validate your rubric. A perfectly built system applying criteria that don't predict performance will apply them consistently to everyone. The graph layer exists to find that out — but it needs a few hundred hires and a couple of years first.
  • It catches noise, not bias. A system that is confidently wrong about a group looks perfectly settled. The swap test finds the proxies you think to test; only outcome tracking finds the rest.
  • Names out is not bias out. Tan et al. (EMNLP, October 2026) removed every name from 4,100 CVs and 18 models still read ethnicity off the languages spoken and gender off the hobbies — and explaining themselves made it worse. So the languages, interests, volunteering and personal-details sections never reach the model here; the reviewer sees them. What survives inside the work history — a club name, a career-break year, a home town — is what the swap test is for, and it now runs by default with language, hobby and volunteering pairs.
  • Polish should not score. AI screeners prefer AI-written CVs, most of all by the same model (arXiv 2509.00462). "No quote, no score" is meant to blunt that; the polish test in the eval report has the scoring model rewrite the CV in shinier language, with no new facts allowed, and requires the score not to move. It is a measurement, not a promise: run it on your model before you trust it.
  • It is not legal advice. The candidate notice and the adverse-outcome explanation it writes are templates. Have whoever owns employment law where you hire approve them, and check the current rules — they moved several times in 2026, and Mobley v. Workday put the vendor in the liability chain, which is one more reason this runs in your environment with no vendor-held score file.
  • Institution tier is deliberately not a parameter. College ranking is the strongest single proxy for socio-economic background in most markets. A test keeps it out.
  • Absence of public work is never a penalty. Employer IP policy, NDAs and unpaid-time inequality suppress GitHub activity independently of ability, so those parameters leave the composite rather than scoring zero.
  • The weights are considered judgement, not measured validity. Reweight for your context, and record who approved it and when.
